一句话边界：

- **拿包前**：用有限卷宗做投资决策——能不能拿？以什么价拿？预期收益率多少？（广而浅、快筛 + 估值 + 风险定价）
- **拿包后（AI Hunter 现状）**：用充分卷宗做价值挖掘——冰山上的固定资产识别 + 冰山下的隐匿资产 / 白手套线索 + 博弈策略，收益最大化。（窄而深）

## 3. 输入卷宗（拿包前初期 5 类）

银行/中介在送包阶段会给到：

| 卷宗 | 性质 | 快筛中的用法 |
| --- | --- | --- |
| 尽调报告 | **别人的结论**（银行/中介已加工） | 复核 + 证伪：抵押物、查封状态、回收预估站不站得住 |
| 法律意见书 | **别人的结论** | 同上，重点核时效、可转让性、程序障碍 |
| 权证 | 原始凭证 | 交叉验证两份报告；核权属、登记、顺位 |
| 诉讼 .zip | 原始凭证 | 核法律状态（未诉/已判/执行中/终本）、程序障碍 |
| 债权 .zip | 原始凭证 | 核四件套（借款合同、借据、放款凭证、担保文件）完整性与一致性 |

关键认知：

- 拿包前材料**并不算少**——有尽调报告和法律意见书这两份结论性文件，所以快筛的核心动作是 **"复核已有结论 + 挖掘增量线索 → 重估收益率 → 投决建议"**，不是"信息太少先粗估"。
- 拿包后通过律师持续补充更多卷宗，原始卷宗与 AI Hunter 现有卷宗存在重叠，拿包前是其子集。
- 真正的增量价值（议价优势）：别人尽调报告里**没写**的部分——隐匿资产、白手套、被低估的回收路径。别人只能按看得见的资产出价，提前嗅到冰山下面的部分才敢报价、报得准。

## 4. 筛选与评估方法论（《不良资产债权项目筛选与评估指引》要点）

### 4.1 递进筛选逻辑（定性）

**合规一票否决 → 担保优先 → 主体/行业 → 区域/处置效率 → 收益与退出**，优选"有抵押、强主体、顺周期、易执行、高安全垫"五大特征。

1. **合规性（一票否决）**：时效过期、债权无效/虚假、权属不清、禁入范围（国家安全/军队/隐性债务/僵尸企业/涉黑涉恶）、无法合法转让 → 直接终止。
2. **担保与抵质押（核心回款抓手）**：有抵押＞有质押＞连带保证＞一般保证＞纯信用；抵押率安全线（快速变现值/债权本息）：住宅 ≥80%、商业/工业 ≥70%、其他 ≥60%；最优"首抵+首封"。
3. **债务人与保证人**：央企/国企＞上市＞龙头民企＞强区域平台＞优质民企＞小微/空壳；看硬资产、现金流、水电税社保，无失信/逃废债。
4. **行业与区域**：优选民生刚需/基建/医疗/新能源/先进制造；回避过剩产能、高污染、高杠杆受限房企；区域：长三角/珠三角核心＞强二线/省会＞地级市＞县域；司法执行环境高效优先。
5. **债权与处置效率**：单户最优本金 500 万—5000 万；资产包 3—10 户、地域集中；法律状态：已胜诉并执行＞已判决未执＞诉讼中＞已仲裁＞未诉；要求 ≥2 条退出路径。
6. **收益与风险定价（最终决策依据）**：收购折扣优选 ≤本金 3 折（优质抵押放宽至 4 折）；底线：预期回收率 ≥ 收购价+资金成本+处置成本+税费；回收周期理想 12—24 个月，>36 个月需高收益补偿。

### 4.2 评分表（定量，总分 100）

| 维度 | 分值 |
| --- | --- |
| 一、合规合法性【一票否决项】 | 20 |
| 二、抵质押担保实力 | 28 |
| 三、债务主体与保证人资质 | 22 |
| 四、行业与区域环境 | 15 |
| 五、处置效率与收益预期 | 15 |

决策门槛：

| 总分 | 评级 | 决策 |
| --- | --- | --- |
| ≥85 | A 优质 | 优先立项、快速尽调、可接受有竞争力报价 |
| 70–84 | B 中等 | 可立项，尽调更深入，压价或增设风控条款 |
| 65–69 | C 风险偏高 | 严格限制介入，需极高折扣安全边际 |
| <65 | D 劣质 | 直接放弃（准入门槛：≥65 方可立项启动详细尽调） |

### 4.3 八不投（快速避坑）

1. 合规死穴（时效过期/债权无效/抵押未登记）；2. 恶意逃债（失联/空壳/转移资产）；3. 劣质抵押物（偏远/专用/价值虚高/恶意租赁）；4. 高危行业；5. 司法"禁区"；6. 定价过高（折扣 >5 折或安全边际不足）；7. 周期过长（>3 年且无阶段性退出）；8. 户均过散（户数多、地域散、单户小）。

## 5. 核心命题：从卷宗到投决

「送包策略 / 尽调 Y/N」两个决策点，本质是从 5 类卷宗估出三个量：

1. **预期回收金额**（天花板）= 债权本息 × 各债项可回收率
   - 看得见的：抵押物/担保估值、查封冻结状态、债务人主体实力
   - 看不见的（AI Hunter 强项）：从有限卷宗嗅出隐匿资产 / 白手套线索信号
2. **回收节奏 / 周期**：法律状态决定折现与 IRR
3. **收购价 vs 回收**：MOIC = 预期回收 / 收购价，按周期折现成 IRR

输出形态：带置信区间的投决建议（拿 / 放弃 + 该价位下预期收益率 X%~Y% + 评分表得分与一票否决项核查结果）。

## 6. 与 AI Hunter 的关系：同一引擎，两种模式

**不另起炉灶做第二套系统。** 复用底层的卷宗理解 + 资产/线索识别能力，差别在数据量、深度和输出形态：

| | 快筛模式（拿包前，新增） | 深挖模式（拿包后，现状） |
| --- | --- | --- |
| 输入 | 5 类初期卷宗（少量） | 全量卷宗（律师持续补充） |
| 动作 | 轻量提取 → 复核证伪 → 评分/估值 | 完整审计 → 资产图谱 → 博弈策略 |
| 输出 | 投决建议 + 收益率区间 | 审计报告 + 隐匿资产/线索 + 督办任务 |

环节映射与缺口：

| 白板环节 | AI Hunter 现状 | 缺口 |
| --- | --- | --- |
| 卷宗资料摄入 | `ingest_graph` + 文档分类工具 | 可复用 |
| 送包策略初筛 | 无 | **新增**：评分表落地（一票否决 + 100 分制） |
| 尽调 / 完整审计 | `full_audit_graph` | 需要"快筛深度"的轻量变体 |
| 收益率 / 估值测算 | 无 | **新增**：回收预估、MOIC/IRR 测算 |
| 追问、修正 | `drilldown_agent_graph` / `extract_correction` | 可复用 |
| 拿包后处置闭环（谈判/物理动作/收款纳税分配） | 仅 `create_tasks` 督办沾边 | 暂不覆盖（执行环节在系统外） |
| 复盘评估 / 入库 | 部分（知识图谱沉淀） | 待定 |

## 7. 已定方向（2026-06-10 决策记录）

| 问题 | 决策 |
| --- | --- |
| ① 快筛挂在哪 | **独立子图 + 专用端点**（`pre_screening_graph` + `/screening/*`），不进 chat router；对评分结果的追问复用现有 drilldown |
| ② 评分自动化 | **机器预填 + 人工确认**：每项给建议得分 + 证据角标 + 置信度，人工可改、留痕；一票否决项必须有证据链且强制人工确认 |
| ③ 估值数据源 | 一期 **提取尽调报告估值 × 快速变现折扣系数 → 人工确认**；二期立项建司法拍卖历史数据库（长期数据壁垒） |
| ④ 定价参数 | **数据库参数表 + 版本化**（资金成本/处置成本/税费，按生效日期版本化），单笔测算可临时覆盖并留痕；归口财务/投决 |
| ⑤ case 建模 | **分开建模**：拿包前为"包（package/商机）"实体；拿包成功后转正式 case，**一个包对应一个 case**（1:1） |

角色分工（决定页面与权限）：

- **老板**：看包、投决（评分确认、定拿/不拿）——投决页面的主用户，出价测算数据仅此角色可见。
- **操作员**：上传包卷宗（复用材料摄入线的上传/校对能力）。
- **律师**：物理行动 + 人工干预出专业意见（评分表中法律类条目的意见方，最终确认权在老板）。

### 8.4 评分项的规则 / LLM 分工（②B 落地）

- **纯规则（代码算，不走 LLM）**：诉讼时效推算（日期数学）、抵押充足率（估值/本息比）、收购折扣率档位、户数金额结构、区域能级（地址→层级映射表）。
- **LLM 预填 + 证据角标**：四件套完整性一致性、转让限制条款、担保方式/顺位认定、法律状态认定、主体性质与经营信号、行业归类。
- **人工为主（机器只留白+给参考材料）**：司法执行环境、保证人代偿意愿、处置路径多样性。
- **硬规则**：一票否决 4 项（时效/债权有效性/可转让性/禁入范围）无论机器结论如何，必须人工点确认才生效；总分 <65 自动建议 D 级放弃。

### 8.5 人工环节 API

| 端点 | 用途 |
| --- | --- |
| `POST /screening/invoke` | 触发快筛流水线（操作员上传后） |
| `GET /screening/{package_id}/scorecard` | 拉评分表草稿（含证据角标，走现有 /evidence/resolve 渲染页图+bbox） |
| `PATCH /screening/{package_id}/scorecard/items/{item_key}` | 改分留痕（modified_by + reason；律师意见也走此通道） |
| `POST /screening/{package_id}/confirm` | 老板定稿：一票否决确认 + 总分/评级/投决结论锁定 |
| `POST /screening/{package_id}/convert` | 拿包后转正式 case（1:1），回填 packages.case_id |

### 8.6 阶段划分

- **M1**：packages 实体 + ingest 复用打通 + 评分表预填（纯卷宗可核项）+ scorecard 人工确认接口。
- **M2**：估值（A+D）+ pricing_params + MOIC/IRR 测算 + 投决建议书。
- **M3**：convert 转 case 通道 + 漏斗统计（看包→尽调→拿包转化率）+ 折扣系数表运营化。
- 二期：司法拍卖历史数据库（喂 estimate_recovery 与"司法执行环境"评分项）。

### 8.7 工程开放点（实现前需定）

1. **筛选期数据的存储归属**：ingest/知识图谱/文件表全部以 case_id 为键。两条路线：
   - **甲（已选定，2026-06-10 直连 ai_hunter 库验证可行）**：为每个包预建"影子 case"，筛选期数据直接挂该 case_id，convert 时只翻状态——存储层零改造。验证结论：
     - `cases.case_type` 的 CHECK 约束已预留 `'资产包'` 枚举值（建表即有，当前 0 条在用），影子 case 直接用它，语义吻合；
