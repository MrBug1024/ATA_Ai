## 三、⚠️ 有缺口（PDF 有要求，设计稿覆盖不全）

### 1. 人员标签缺 2 维
PDF 列 **7 维**，代码仅 **5 维**，缺：
- **实人认证信息**：身份证 / 银行卡 / 安诺编码 / 邀请码（与计酬、身份溯源强绑定）。
- **从业经历标签**：银行风控 / AMC / 经济审判法官 / 经侦 / 纪检稽查 / 矿山运营等 9 项。
> 成本最低、与 06 直接对接，建议优先补齐。

### 2. 净回款扣减项模型
- PDF「净回款 = 回款 −（执行申请费/司法评估费/拍卖费/悬赏公告/异地差旅/仓储/开锁搬迁/续封续冻/以物抵债税费/税金）」。
- 03 回款闭环目前只到"回款"，**缺一套可配置的扣减项清单 + 净回款计算**，才能算"净回款 20%"分成。

### 3. 客户报备时效
- PDF「客户报备有效期 60 天，过期重新报备确权」。
- 可复用 05 司法时效看板的"倒计时/到期"机制，但**报备对象是客户而非案件时效**，需要新的实体与触发。

### 4. 任务派单增强
- PDF 四 + 六「任务四分类（专家/尽调/传达/营销）、属地优先、标签智能匹配、自动查重」。
- 现有 `create_tasks` 节点较简单，**缺分类、属地匹配、标签匹配、自动查重**。

## 四、❌ 完全缺失（PDF 核心增量，现有系统无对应）

### 1. 三级（四级）分销计酬引擎 —— 头号大块
- 邀请码绑定上下级关系树；单层级限 5 人、间接不限。
- 分层提成：下级 10% / 下下级 5% / 再下级 2.5%（且四级存在反向分成）。
- "分成仅来自增量任务收入"——需从下级实得中扣减计算。
- 休眠机制：KPI 不达标自动休眠、不能接单、休眠不影响分成、重新激活需审定。
- 结算：统一代扣个税、可开增值税发票、《众包计酬结算表》。
- **⚠️ 头号歧义**：PDF 标题"三级"，正文写到"四级"，且反向分成规则自相矛盾 → **落地前必须找业务方澄清几级、反向分成是否成立**。

### 2. 众包确权与查重 —— 第二大块
- 先到先得：访谈每件 500 元只付第一个，**时间戳确权**。
- 系统自动查重 + 实时反馈查重结果。
- 适用：同一线索 / 同一客户 / 同一项目，最先上传报备者享权益，系统自动判无效。

### 3. 争议裁决流程
- 查重争议：牵头领导 5 工作日内裁决。
- 计酬争议：书面异议 → 项目经理 3 工作日答复 → 不服上诉牵头领导 → 5 工作日终裁。
- 需要一套**状态机 + SLA 时限 + 角色审批链**。

---

## 五、建议优先级（均需业务方确认后再排期）

1. **立即澄清歧义**：三级 vs 四级计酬到底几级、反向分成是否成立（文档内部矛盾）。
2. **补全人员标签 2 维**（实人认证、从业经历）——成本最低，直接对接 06。
3. **新立两块大设计稿**：
   - `07-众包计酬与分销引擎`（邀请码圈链 + 分层提成 + 休眠 + 结算）
   - `08-确权查重与争议裁决`（时间戳确权 + 查重 + SLA 审批链）
4. **扩展已有看板**：净回款扣减项挂 03 回款闭环；客户报备时效挂 05 时效看板，复用 case 锚点。
5. **增强任务派单**：四分类 + 属地/标签匹配 + 自动查重。

---

## 六、一句话结论

现有设计稿（01~06）已把**报告、估值、回款、修正、时效、权限/标签**六条主线打好基础；
PDF 相对系统的**最大增量是"钱"这条线**——**三级（四级）分销计酬 + 众包先到先得确权/查重/争议裁决**，目前完全空白，且计酬层级表述自相矛盾，是落地前的首要卡点。
