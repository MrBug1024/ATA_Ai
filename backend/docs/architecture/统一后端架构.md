# AI Hunter 统一后端架构

## 目标

原平台的 AI 编排服务和 NPA 领域服务已合并为一个部署单元：一个 Python 包、一个 FastAPI 应用、一个 Uvicorn 进程、一个公开端口。合并不改变已有 API 路径、请求模型、响应模型、数据库或业务口径。

```text
Web :3000
  └─ AI Hunter API :8081
      ├─ ai_hunter.app
      │   ├─ /auth、/me、/companies、/users、/roles
      │   ├─ /chat、/files
      │   └─ /graph、/evidence、/cases（治理与分析）
      └─ ai_hunter.domain_engine
          ├─ /api/ingest
          ├─ /api/cases、/api/case
          ├─ /api/audit
          └─ /api/tasks、/health
```

## 代码边界

- `ai_hunter/app/main.py`：唯一应用工厂和部署入口。
- `ai_hunter/app/graph`：LangGraph 主图、业务线子图、状态和确定性报告口径。
- `ai_hunter/app/tools`：智能体可发现的工具注册层。
- `ai_hunter/app/services`：AI 编排层的数据/领域调用适配器。
- `ai_hunter/domain_engine`：案件、文档、企业、审计引擎和任务的确定性实现。
- `ai_hunter/domain_engine/integration.py`：领域路由注册桥；负责方法冲突检测和领域 API 审计日志接入。

## 配置

- 对外监听：`APP_HOST`、`APP_PORT`。
- 内部领域调用：`UNIFIED_API_BASE_URL`，默认 `http://127.0.0.1:8081`。
- 原六个分服务 URL 变量仅用于紧急回滚兼容，正常部署保持为空。
- 前端只配置 `NEXT_PUBLIC_API_BASE_URL`。
- 业务数据库和 LangGraph 数据仍使用现有数据库配置，本次合并没有执行 DDL 或迁移数据。

## 不变性保障

- `tests/domain_engine/test_unified_registration.py` 锁定原领域服务全部路径与 HTTP 方法，同时检查关键 AI 路径。
- 领域模型和 endpoint 函数直接复用，没有通过代理改写请求或响应。
- `pytest` 默认隔离真实外部状态，避免维护测试误写生产数据库；真实冒烟必须显式运行 `scripts/` 下的脚本。
- 前端仍通过 `lib/backend` 作为唯一后端契约层，页面和 hooks 不直接拼 URL。

## 当前兼容实现

AI 工具调用领域能力时仍使用本机 HTTP 地址，以保持原超时、错误映射和服务令牌语义。它已是同一进程内的回环调用，不再依赖第二个后端进程。后续若改为进程内函数调用，必须先为每个工具建立等价契约测试，不能改变异常和权限行为。
