# 数据提取问题排查指南

## 问题概述

你的FastAPI服务在解析《钟山区老鹰山镇晨光煤矿法律尽职调查报告.pdf》时，虽然成功分类了12个文档类别，但部分类别（财务报表、不动产权证、勘探报告、环评批复）的LLM提取返回了空数据，导致入库失败。

## 根本原因

1. **LLM提取返回`None`或空字典`{}`**
   - 文档中可能没有完整的结构化数据（如完整的财务报表）
   - LLM理解偏差或敏感词拦截
   - 提取Prompt不够鲁棒

2. **日志不够详细**
   - 无法看到LLM的原始响应
   - 无法判断是文档问题还是LLM问题

3. **入库逻辑对空数据处理不明确**
   - 空数据触发警告但不报错
   - 用户无法区分"文档无数据"和"提取失败"

## 常见问题

### Q1：为什么有些类别分类成功但提取失败？

**A**：分类和提取是两个独立步骤：
- **分类**：基于关键词匹配（如"财务报表"、"资产负债表"）
- **提取**：基于LLM理解文本结构并提取字段

文档中可能有"财务状况"章节（触发分类），但没有完整的资产负债表（导致提取失败）。

### Q2：如何判断是"文档无数据"还是"提取失败"？

**A**：应用补丁后，日志会明确区分：
```
⚠️  LLM返回空字典（文档中可能无此类数据）  ← 文档无数据
❌ LLM异常=...                              ← 提取失败
❌ JSON解析错误                             ← 提取失败
```

### Q3：如何提高提取成功率？

**A**：
1. **优化PDF转Markdown质量**：使用MinerU的高质量模式
2. **改进分段策略**：避免将表格切断（修改`_split_segments`函数）
3. **调整提取Prompt**：增加示例或放宽字段要求
4. **换用更强的模型**：Gemini 2.5 Flash > MiniMax M2.5

### Q4：采矿权和不动产数据为什么是空的？

**A**：从日志看，采矿许可证提取成功了：
```
[DocParser][Step 4/4] 入库[采矿许可证] | 数据类型=dict | 字段={'mine_name': '六盘水市钟山区老鹰山镇晨光煤矿', ...}
```

但不动产权证提取失败：
```
[DocParser][Step 4/4] 入库[不动产权证] | 数据类型=dict | 字段=None
```

可能原因：
- 该PDF是法律尽职调查报告，只引用了权证号，没有完整的权证信息
- 不动产信息分散在多个章节，被分段切断
- LLM敏感词拦截（权证号、地址等）

**解决方法**：
1. 运行单类别测试，手动复制不动产章节测试提取
2. 检查`llm_client.py`的脱敏日志
3. 如果确实无完整数据，考虑手动录入或从其他文档补充
