# 04 · 文字修正 → 权威订正 + 可追溯（Tier 2 决策三）

> 状态：**✅ 已实现并合入**。新表 `case_correction` + `correction_service.py` + `extract_correction` 写库 + `fetch_full_context` 加载期应用 + `routes_corrections.py` 接口。pytest 181 passed，真实库（case 116）验证 写入/自动 supersede/加载 全通过。

## 1. 背景与问题

文字修正（口头订正，如"水西南路房产估值不对，按 800 万"）此前只在会话内叠加：

- `re_audit` → `extract_correction` 抽 `(标的, 指令)` → 仅写 `state["user_corrections"]` / `state["correction_records"]`（随 checkpoint）。
- **只本线程生效**、**不写库**、**无时间/操作人/范围** → 无法追溯"谁何时改了什么"，也非案件权威数据，只是每次报告的 prompt overlay。

决策三目标：升级为**权威订正**（写库、加载期应用、跨会话/跨人生效）+ **可追溯**（时间/操作人/标的/指令/来源/范围/状态）。

## 2. 数据模型：`case_correction`（[sql/case_corrections.sql](../../sql/case_corrections.sql)）

| 列 | 说明 |
|---|---|
| id PK / case_id | |
| target / instruction / source_query | 标的 / 强制指令 / 原始话术 |
| operator_id / operator_name | 操作人（取自 ChatRequest，账号体系上线前可空） |
| **operator_meta** JSONB | **预留**：账号体系上线后回填角色 / 专业标签（多选），用于人岗匹配与分权审计 |
| scope | 生效范围，默认"全案" |
| origin | chat（对话抽取）/ manual（接口人工录入） |
| status | active / superseded / revoked |
| superseded_by | 自动 supersede 时指向覆盖它的新订正 id |
| created_at / updated_at | 追溯时间 |

索引：`idx_case_correction_active`（按案查 active，加载期用）、`idx_case_correction_case`（全量含历史，追溯用）。

## 3. 逻辑

### 3.1 写入（权威化）
`extract_correction`（[corrections.py](../../ai_hunter/app/graph/nodes/corrections.py)）抽出 `(标的,指令)` 后，除会话叠加外**写库**（`add_correction`，operator 取自 state）。写库 best-effort：库不可达时仅吞日志、不拖垮重审。

### 3.2 自动 supersede（最新权威覆盖）
`add_correction`（[correction_service.py](../../ai_hunter/app/services/correction_service.py)）写入新 active 订正后，把**同 (case_id, target) 的其它 active 订正置 superseded**（`superseded_by` 指向新 id）。效果：每个标的只有一条 active（apply 端干净），旧值保留作历史可追溯。

### 3.3 加载期应用（跨会话/跨人生效）
`fetch_full_context._merge_corrections`（[fetch_full_context.py](../../ai_hunter/app/graph/nodes/fetch_full_context.py)）在拉全量上下文时，从库加载该案 **active 订正**，与本轮会话叠加**并集去重**后写入 `user_corrections` / `correction_records`：

- 库有订正 → **DB 权威优先，任何 full_audit（不止 re_audit）、任何会话/人都自动应用**；
- 库不可达（返回 `{}`）→ 不覆盖，保留纯会话叠加（离线/降级仍可用）；
- 并集去重保证：即便本轮写库失败、订正只在 overlay，也不丢。

下游报告段 / 下钻 agent 的消费逻辑不变（仍读 `user_corrections` / `correction_records`）。

### 3.4 追溯 + 人工管理（[routes_corrections.py](../../ai_hunter/app/api/routes_corrections.py)）
| 接口 | 方法 | 作用 |
|---|---|---|
| `/cases/{id}/corrections` | GET | 列订正；`include_history=true` 含 superseded/revoked，供追溯审计 |
| `/cases/{id}/corrections` | POST | 人工录订正（origin=manual，触发自动 supersede） |
| `/cases/{id}/corrections/{cid}/revoke` | POST | 撤销（status=revoked，下次审计不再应用） |

## 4. 与上传材料 supersede 的关系

两条权威更新路径并存，理念对齐：
- **材料驱动**：ingest → `reconcile_graph_delta` 把旧 claim supersede + 写对账台账（证据驱动）。
- **文字驱动**：本特性 `case_correction`（人工订正驱动）。

两者都跨会话权威、可追溯、可被复盘/审计可见。
