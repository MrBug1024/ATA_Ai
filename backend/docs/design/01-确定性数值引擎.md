## 1. 目标与定位

把审计报告里的**核心数字从 LLM 手里收回到代码**：逐项去毒净值、债权脱水、总账、NPV、V_net、回收率、三层回款预测。LLM（段落专家 agent）只负责把引擎算好的数字写成表格/结论，**不得重算**，从而：

1. **治段间数字打架**：第 2 段算的 V_net 与第 5 段引用的 V_net 永远一致。
2. **固化估值口径**（会议要求）：万元单位、回收率只算终审本息、风险归零等规则写进代码。
3. **可复现、可审计**：同样输入永远同样输出，复盘时可追溯每个数字怎么来的。

**定位**：纯计算 + 数据质量标记，无 LLM、无副作用（不写业务库）。是报告重构（设计方案 02）的地基，**不依赖 agent 怎么拆**，故第一个做。

## 2. 上游已有能力与本引擎定位（基于 NpaDemo 源码实测）

上游数据服务仓库：`jonymonkey089-wq/NpaDemo`（`fastapi_server/main.py`）。读源码后确认：**上游不是空白，已有真实的去毒/时效/行为引擎**，本引擎定位据此从"从零重算"修正为**"消费上游去毒明细 + 自己做口径层"**。

→ **逐项去毒明细、时效看板、行为扫描不重造**，本引擎直接消费。

### 2.2 上游口径与报告口径冲突（本引擎要解决的）
| 维度 | 上游 NpaDemo | 报告要求 | 处理 |
|---|---|---|---|
| 回收率分母 | `total_net / SUM(total_claim)`（含罚息/复利） | 只算终审**本金+利息** | 本引擎**用本息分母重算** |
| 归零 | `max(discount, 0.05)` 5% 下限**防归零** | 极端情况**直接归零** | 本引擎**口径层覆盖**（满足阈值则置 0） |
| NPV/折现/三层时间窗 | **完全没有**（纯静态折扣，无时间价值） | 核心要求 | 本引擎**新增** |
| 折扣系数 | 硬编码 | 可能要客户可调 | 本引擎**参数化**（见 §10 待确认） |

### 2.3 数据质量（实测 case 116，多为测试数据）
- `gross_value=0.0`、`mine="牛"`、`total_net=total_gross=129219380` 但单项 net=0 → case 116 是**测试数据**，生产数据代表性待确认（见 §10）。
- `claims`：claim[1] 有 principal/interest/penalty 拆分但 `total_claim` 与之不自洽；claim[0] 仅有 total_claim、拆分全 None → 本引擎按本息重算时，拆不出的**打标 `unsplittable`**，不静默用 total_claim 顶替。

## 3. 输入契约（审计 API full_context → 规范化模型）

数据源：`fetch_full_context` → `get_full_context_sync(case_id)`（[fetch_full_context.py](../../ai_hunter/app/graph/nodes/fetch_full_context.py)）。引擎读取 heavy payload 里的 `data`，规范化为下述内部模型（容错：缺字段给 None 并打标，绝不抛错中断报告）。

### 3.1 债权 `claims[]`（实测字段）
`claim_id, principal, interest, penalty, total_claim, lien_priority, litigation_status, guarantee_type, collateral_desc`
- 回收基数口径：`recovery_base = principal + interest`（终审本金+利息）。
- 劣后：`penalty`（罚息）+ 复利/迟延利息 → 估值中默认 **0**，仅作谈判筹码。
- 若 `principal`/`interest` 缺失 → `recovery_base = None`，标 `unsplittable=True`（如 claim[0]），不静默用 total_claim 顶替。

### 3.2 不动产 `real_estate_evaluations[]`（实测字段）
`id, project_name, property_address, property_usage, gross_value, net_value, discount_factors{风险名:系数}, overall_rating, seal_status, objection_status, has_title_objection, physical_occupation, mortgage_status, lien_priority, lease_status, lease_start, lease_end, co_owner_info`
- 去毒净值口径见 §4.2。

### 3.3 采矿权 `mining_evaluations[]`（实测字段）
`id, mine_name, coal_type, mine_scale, production_scale, annual_capacity, proved_reserves, calorific_value, estimated_value, transfer_base_price, permit_expiry, safety_permit_status, env_approval_status, in_ecological_redline, mining_status, overall_rating`

### 3.4 其它
- `guarantors[]`：`guarantor_id, entity_name, guarantor_type, guarantee_type, spouse_name`（配偶连带看 `spouse_name`）。
- `debtors[]`：`debtor_id, entity_name, legal_representative, actual_controller, registered_capital, operating_status, uscc`。
- `engine_results.valuation_squeeze` / `engine_results.deadline_scan`：上游引擎结果，作为参考/交叉校验输入。

> 命名提示：报告 prompt 第 2.1 段写的是 `real_estate_valuations`，真实键是 `real_estate_evaluations`（latent bug）。引擎读正确键并喂干净数据给 agent，agent 不再接触原始键名。

## 4. 计算规格（口径写进代码）

### 4.1 债权脱水
- `真实博弈基数 = Σ recovery_base`（仅可拆分的 claim 计入）。
- `劣后总额 = Σ(penalty + 复利 + 迟延)`（展示用，不进估值）。
- 输出每笔 claim 的 `recovery_base / 劣后 / lien_priority / litigation_status`，及不可拆分清单。

### 4.2 不动产 / 采矿权去毒净值（消费上游 + 口径层覆盖）
- **基线净值**：直接取上游 `engine_results.valuation_squeeze.real_estate_valuations[].net_value` / `mining_valuations[].net_value`（上游乘法折扣模型已算好，含 `discount_factors`/`verdict`）。**不重算逐项折扣**（避免与上游领域逻辑重复且漂移）。
- **口径层覆盖（本引擎做上游没做的）**：
  - **归零**：上游有 `max(discount,0.05)` 5% 下限防归零；本引擎按**极端风险阈值**（查封+案外异议+强占叠加等，阈值见 §10 待确认）将该资产净值**置 0**，覆盖上游下限。
  - **基数缺失标记**：上游 `gross_value=0`/数据缺 → 标 `is_estimated=True`，留给段落 agent 盲估并标 `*(LLM盲估)*`。
  - 交叉校验：若上游 `total_net_value` 与逐项 `Σnet_value` 不一致（实测 case 116 出现），以逐项为准并记 `data_quality` 警告。

### 4.3 采矿权补充
采矿权同 §4.2 消费上游 `mining_valuations[].net_value`。合规红旗（`permit_expiry` 过期、`in_ecological_redline`、安全/环评异常、查封）上游已纳入折扣；本引擎只在极端叠加时触发归零。

### 4.4 总账聚合
按资产类型输出：`项数 / 账面总值 / 去毒总净值 / 平均折扣率`（不动产、采矿权、合计）。

### 4.5 NPV 与回收率
```
V_rec = Σ ( P_n · W_n / (1 + r)^t_n )
```
- `P_n`：第 n 笔资产去毒净值；`W_n`：回款概率权重；`t_n`：所属时间档的年化期数。
- 三层时间档：T1 极速(0-3月) / T2 中效(6-15月) / T3 长尾(12-24+月)。
- `V_net`：脱水后净回收现值；`总回收率 = V_net / 真实博弈基数`（分母为**本息**，已决策 2026-06-15，与上游 `total_claim` 口径分离）。

### 4.6 参数化与覆盖原则（已决策 2026-06-15）
**所有口径参数做成可配置，下游可覆盖上游。** 即：
- 折现率 `r`、三层时间窗与年化 `t_n`、资产→时间档归类、权重 `W_n`、金额小数位、极端归零阈值、（必要时）折扣系数 —— 全部集中在配置（ai_hunter `settings`/常量表），**不散落、不写死在 prompt 或函数内**。
- 凡上游 NpaDemo 也提供的值（如逐项折扣系数、recovery_rate），下游配置可**覆盖**：默认消费上游，配置开启则用下游口径。
- 每次计算把**本次实际所用参数**写进 `computed_metrics.params`，便于复盘追溯。
- → 因此这些参数不再是"阻塞实现"，而是"带默认值的配置项，客户随时可调"。

## 5. 数据质量标记（给段落 agent 的信号）

引擎对每个计算对象输出标记，段落 agent 据此决定话术：
- `is_estimated`（基数缺失，需 `*(LLM盲估)*`）
- `unsplittable`（债权拆不出本息，需说明口径受限）
- `missing_fields: [...]`（缺哪些字段，关联 `[需补卷清单]`）
- `risk_flags: [...]`（查封/案外异议/红线/证照过期等）
- `zeroed: bool`（是否触发归零，附原因）

## 7. 金额格式化服务（场景差异化，ROADMAP 决策二补充）

引擎输出**原始数值**；格式化是独立工具，按产物类型套用：
- **审计报告**：万元、保留 4 位小数、**取消千分位**。
- **法律文书 / 函件**：元、**加分节号（千分位）**。
- 实现为 `format_amount(value, scene)`，集中一处，报告/文书各自调用，不在 prompt 硬写。

## 10. 决策与待确认

**A. 口径参数 —— ✅ 已决策：做成可配置（带默认值），客户随时可调，不阻塞实现**
- 默认值（实现时落配置，可改）：折现率 `r=12%`；三层时间窗 T1(0-3月)/T2(6-15月)/T3(12-24+月)；金额小数位以**会议口径 4 位**为默认（现 prompt 2 位作废）；极端归零阈值待客户给（默认先用保守规则，配置可调）。
- 详见 §4.6 参数化与覆盖原则。

**B. 上下游边界 —— 已决策**
1. **回收率分母**：✅ 下游用 `principal+interest` 重算（排除 penalty/delayed_interest/复利），上游 `recovery_rate` 仅参考。
2. **逐项折扣系数**：✅ 保留在上游（领域逻辑），下游配置可覆盖（§4.6）；建议上游后续做成可配置。
3. **去毒明细消费契约**：本引擎稳定消费 `engine_results.valuation_squeeze.{real_estate_valuations,mining_valuations}[].{net_value,discount_factors,verdict}`；上游改字段名需通知（纳入契约文档，见 NpaDemo-review §1.3）。

**C. 仍需向客户/数据侧确认的事实（不阻塞架构，影响校准）**
4. **生产数据代表性**：case 116 多为测试数据（gross=0、mine="牛"、total_net=total_gross）。需一个数据完整的真实案件做端到端校准。
5. **claims 拆分完整性**：生产数据 `principal/interest/penalty/delayed_interest` 是否稳定齐全、缺失比例（决定 `unsplittable` 兜底策略的重要性）。
6. **极端归零阈值**的具体规则（客户给定后填入配置默认值）。
