# 05 · 司法时效看板（红黄绿 + 倒计时）（Tier 2-5）

> 状态：**✅ 已实现并合入**。确定性引擎 `deadline_board.py` + `GET /cases/{id}/deadline-board` 接口；reconcile 风险汇总改用同引擎口径统一。pytest 188 passed。

## 1. 背景与定位

时效数据源是审计引擎 `engine_results.deadline_scan`（audit API `/api/audit/deadline-scan`）。此前只被两处消费：报告第 4 段（LLM 写成四级**叙述文字**，定格快照）+ 进度看板 risk_alerts（仅过期/红的**计数汇总**）。缺的是**可被前端渲染、随日期刷新的结构化红黄绿看板**。

定位（独立确定性接口，不改报告本身）：
- **倒计时（剩余天数）是日期相对的、动态的** → 必须能实时查询，报告快照满足不了 → 独立接口。
- **时效是审计引擎产出**，生命周期不同于回款 → 不塞进 `/progress` response，但进度看板 risk_alerts 可联动跳转。
- **红黄绿分级走确定性代码重算**（不信上游出报告那刻的分类），阈值 env 可配。

## 2. 确定性引擎 `graph/deadline_board.py`

`compute_deadline_board(deadline_scan, *, today, red_days, yellow_days)`：纯函数。

- **容错归一**：`deadline_scan` 是外部 API 产出，单项字段名未在仓库固定 → 用 `_FIELD_ALIASES` 别名列表兜底取「到期日/关联资产/建议动作/类型」；条目从多种数组键（`expired_alerts`/`red_alerts`/`alerts`/…）或任意 list 值摊平收集。**真实字段确认后只改 `_FIELD_ALIASES` 一处**。
- **倒计时**：`remaining_days = (到期日 - today).days`，到期日缺失 → unknown 组。
- **红黄绿四级（确定性重算）**：
  - 已过期：remaining < 0
  - 🔴 红：0 ≤ remaining ≤ `red_days`（默认 30）
  - 🟡 黄：`red_days` < remaining ≤ `yellow_days`（默认 90）
  - 🟢 安全：remaining > `yellow_days`
  - 未知：无到期日
- 组内按 remaining 升序（最紧急在前）；上游单项其它字段透传保留。
- 返回 `{today, thresholds, counts{expired/red/yellow/safe/unknown/total}, groups{...}}`。

阈值 env：`DEADLINE_RED_DAYS=30` / `DEADLINE_YELLOW_DAYS=90`（见 .env.example）。

## 3. 接口 `GET /cases/{id}/deadline-board`（routes_deadline.py）

调 `audit_deadline_scan_sync(case_id)` → `compute_deadline_board` → 结构化 JSON。审计引擎不可达时返回空看板 + `available=false`，不报 500。

响应：`{case_id, available, today, thresholds, counts, groups}`，每项含 `type/due_date/remaining_days/related_asset/action/level`。

## 4. 三者分工（不重复、不耦合）

| 产物 | 形态 | 用途 |
|---|---|---|
| 报告第 4 段（report_s4.txt，**不动**） | LLM 叙述快照 | 报告内的法律解读、失权后果与补救路径 |
| `GET /deadline-board`（本特性） | 确定性结构化、可刷新 | 前端红黄绿看板、倒计时 |
| 进度看板 risk_alerts | 过期/红计数汇总 | 看板提醒条，联动跳转时效看板 |

进度看板 risk_alerts 的时效汇总（`reconcile_report._aggregate_risk_alerts`）已改用 `compute_deadline_board` 的 counts，与本接口**口径统一**。

已对照上游 NpaDemo `fastapi_server`（`/api/audit/deadline-scan` + `deadline_alerts` 表）并直连 live API（case 116）双重确认，`_FIELD_ALIASES` / `_LIST_KEYS` 已是真实字段：
