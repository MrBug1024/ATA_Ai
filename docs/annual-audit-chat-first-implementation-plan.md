# AI 会计师年度审计智能体实施方案

## 目标与边界

项目采用“AI 对话驱动年度审计”的产品形态。用户仍从原平台熟悉的对话界面进入，通过对话创建或选择年审项目、上传资料、执行完整年审、下钻分析、查看证据和关系图谱，并按模板生成底稿与年度审计报告。

运行时只有年度审计业务域，后端只有一个 `8080` 服务。历史项目的文档、提示词、路由、工具、数据模型、样本数据和数据库连接均不进入新项目。

## 可复用能力

- AI 对话与 SSE 流式响应
- LangGraph 编排、检查点与会话记忆
- 文件上传、OCR、结构化解析和后台摄入
- 断言、证据定位、页码和引用链
- 关系图谱与证据抽屉
- 报告版本、导出和模板化生成
- 身份认证、租户隔离、角色权限和管理后台
- PostgreSQL、Redis、MinIO 的通用平台存储实现

## 年度审计业务主链路

1. 用户登录并进入 AI 对话。
2. 创建或选择年度审计项目，主数据确定被审计单位和会计年度。
3. 上传财务报表、科目余额表、序时账、凭证、应收明细、银行流水、收入支持资料、函证和税务资料。
4. 系统识别资料类别，解析结构化数据，形成资料完备度和异常清单。
5. AI 执行销售与应收、货币资金、收入截止性、账龄、函证、科目勾稽、凭证和流水异常分析。
6. 所有重要结论绑定原始文件、页码、片段和图谱关系。
7. 生成审计发现、调整建议、工作底稿草稿和年度审计报告草稿。
8. 用户继续在同一会话下钻、纠正事实或补充资料，系统基于原始数据和更正台账重新生成。

## 数据架构

| 存储 | 本地地址 | 职责 |
|---|---|---|
| PostgreSQL | `127.0.0.1:55432/ata_agent_platform` | 会话、checkpoint、身份权限、证据、关系图谱 |
| MySQL | `127.0.0.1:53306/ata_ai` | 年审项目、财务结构化数据、发现、底稿、报告、任务 |
| Redis | `127.0.0.1:56379` | 大对象缓存和任务状态 |
| MinIO | `127.0.0.1:61000` | 原始资料、解析产物、报告文件 |

四类存储均使用 `ata-annual-audit-local` Docker Compose 和独立命名卷。配置层固定年度审计业务域、MySQL 数据库名和后端端口，拒绝回退到其他项目数据库。

## 单服务接口

`uvicorn ai_hunter.app.main:app --host 0.0.0.0 --port 8080` 同时提供：

- `/auth/*`、`/me`：登录与身份
- `/chat/*`：对话、会话和对话内上传
- `/api/cases`、`/api/audit/*`：年度审计项目和确定性业务上下文
- `/files/*`：资料摄入与进度
- `/evidence/*`、`/graph/*`：证据和关系图谱
- `/cases/{case_id}/corrections`：事实更正台账
- `/companies`、`/users`、`/roles`：管理后台

前端仅使用 `NEXT_PUBLIC_API_BASE_URL=http://localhost:8080`。

## 分阶段实施

### 第一阶段：可演示闭环

- 独立本地数据底座和最高权限账号
- 年度审计项目主数据
- 对话内上传客户资料
- 财务结构化数据导入和资料完备度
- 销售与应收、货币资金两条确定性分析
- 完整年审报告草稿、证据引用和图谱查看

### 第二阶段：专业能力加深

- 收入截止、函证、账龄、减值、关联方、银行未达账项
- 审计抽样、重要性水平和调整分录
- 客户模板驱动的底稿与报告生成
- 复核、签发和版本治理

### 第三阶段：完整项目化

- 全科目循环和税务协同
- 多组织、多项目、项目组权限与复核链
- 模型评测、规则版本、提示词版本和审计日志
- 私有化部署、备份恢复、监控告警和容量规划

## 验收标准

- 关闭历史项目服务后，年度审计登录、对话、上传、分析、证据、图谱和报告仍可独立运行。
- OpenAPI 不暴露历史业务专属路由。
- 代码、提示词、测试样本和运行文档不包含历史业务数据。
- 所有浏览器请求只指向 `localhost:8080`。
- 年审数据只写入 `ata_agent_platform` 平台库、`ata_ai` 年审事务库、年度 Redis 命名空间和年度 MinIO bucket。
- 年度审计主链路具备自动化测试，并完成浏览器端到端回归。
