# 年度财务报表审计生产交付运行模型

## 1. 服务边界

本系统服务的对象是会计师事务所和注册会计师执行的企业年度财务报表审计。
它不是工商年报公示、所得税汇算清缴、税务稽查、专项审计或自动签发审计意见的
工具。AI 只能生成线索、结构化事实和草稿；业务约定、独立性、专业判断、复核、
签字和盖章必须由具备资格的人员完成。

以下资料明确不能作为原始账务资料已齐备的证明：

- 历史审计底稿、培训案例、报告模板或客户提供的派生工作表。
- 缺少文件哈希、来源、页码/工作表/单元格/行号的文字摘录。
- AI 的分析结果、规则命中结果或“0 项异常”结果。

new_docs 中的北京有限公司案例属于程序目录、字段映射和验收测试样本。其
README_拆分说明.md 已说明没有原始总账、完整序时账和真实银行流水，因此不得
用于签发真实项目。

## 2. 真实项目输入

立项时必须冻结被审计主体、报告期、审计用途、适用会计准则、行业/监管身份、
会计师事务所、项目合伙人、签字注册会计师、独立性结论、数据分级、存储地域和
模型数据策略。

执行前至少按项目风险收集并分类下列材料：

- 财务报表及附注、科目余额表、完整总账/明细账、序时账/凭证、期末调整分录。
- 销售、采购、存货、薪酬、银行、固定资产/长期资产的原始支持材料。
- 会议纪要、关联方、诉讼担保、纳税、期后事项、持续经营和管理层声明资料。
- 审计师控制的函证台账、发函、回函、可靠性评价和替代程序记录。

上传文件、OCR/解析结果、结构化数据和结论必须分层保留。每项程序的证据引用需
包含当前项目的源文件 ID 及页、块、工作表、单元格或行定位；服务端会校验其归属，
不能以外部项目或虚构引用完成程序。

## 3. 项目状态与门禁

状态流转如下：

    预检 -> 承接/独立性 -> 计划 -> 现场执行 -> 完成 -> 三级复核
    -> 待签发 -> 已签发 -> 归档

项目工作台会初始化以下受控程序：

- 承接、独立性、业务约定、风险评估、重要性、总体策略和内部控制了解。
- 销售与收款、采购与付款、存货、薪酬与人事、资金、固定资产与长期资产六大循环。
- 关联方、税务、会计估计/减值、诉讼与或有事项、期后事项、持续经营、披露、
  错报汇总、管理层声明和完成阶段检查。

每个程序保存认定、风险、所需资料、样本、证据、例外、替代程序、结论、编制人、
修订记录和适用政策版本。资料缺失只能使程序处于 blocked、in_progress 或
not_applicable（必须说明原因），不能自动产生“无异常”。

正式签发门禁会同时检查：

1. 承接已批准、独立性已清除、项目画像完整。
2. 每个适用程序均已完成并有当前项目的可定位证据和结论。
3. 所有开放风险发现、函证异常和未执行替代程序均已解决并复核。
4. 项目经理、部门复核人、项目合伙人的最新决定均为批准，且没有被较低级别的
   后续修改覆盖。
5. 适用法规/知识发布和事务所规则集均已批准、有效且冻结到项目。
6. 正式报告已由项目合伙人身份提交人工签字确认、签名成果物引用和 SHA-256。

门禁未通过时，系统只能保存“草稿”成果物。自动生成的 DOCX/XLSX 已明确标为草稿，
不会被标记为已发布的正式审计报告。

## 4. 知识与规则治理

知识资料按以下层级管理，检索和规则引用都保留来源、发布机关、URL、原件 SHA-256、
版本、条款定位、发布/生效/失效日期、复核人和批准人：

1. 法律、会计准则和审计准则。
2. 监管解释、专业指引和行业专题。
3. 会计师事务所方法学、模板和质量管理政策。
4. 历史项目经验、培训案例和参考资料。

法规和准则按条/款/段，模板按程序/字段切分。每个知识版本须经历
draft -> reviewed -> approved；只有由已批准版本组成、且仍在有效期内的
published 知识发布可参与项目。规则集同样需要逐条批准后发布。

规则类型必须标明为下列之一：

- mandatory_requirement：法律、准则或监管强制性要求，必须绑定条款位置。
- firm_methodology：经事务所批准的方法学。
- data_check：可复现的数据校验。
- risk_signal：风险线索，不能直接表述为错报或审计意见。

客户材料中出现的函证比例、抽样比例和重要性经验值不自动成为法律规则。它们必须
由事务所作为版本化方法学明确适用前提、风险、例外和替代程序后才能发布。

## 5. 对外交付

正式对外成果由事务所按适用法规形成，包括审计报告及经审计财务报表和附注。系统
可同时形成并保留：

- 客户/治理层：资料缺口清单、函证异常、调整及未调整错报汇总、重大事项沟通、
  管理建议书。
- 事务所内部：承接记录、风险与重要性、审计策略和计划、程序底稿、证据索引、
  复核意见、规则/知识版本、签发日志和归档清单。

归档必须引用完整归档清单及 SHA-256，保管期限不得少于签发日起十年；系统记录
签发后 60 日归档时限是否逾期，但不会以逾期为由丢弃或覆盖档案。

## 6. 上线运行顺序

1. 执行独立年审 MySQL/PostgreSQL 迁移 009 与资料类别迁移，确认无失败表。
2. 从官方来源导入并由会计/审计专家审批首期法规、准则和事务所方法学版本。
3. 发布知识发布和规则集；为项目冻结适用于报告期和项目画像的版本。
4. 创建项目并完成承接、独立性、数据安全和签字人员画像。
5. 上传并分类原始材料，完成源文件、页/块/单元格定位和结构化导入。
6. 逐项完成程序、函证、风险发现处理与三级复核；每次发布门禁评价会留下审计日志。
7. 项目合伙人以人工签名成果物完成签发，随后归档。
